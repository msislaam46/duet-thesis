\chapter{Threat Model and Problem Statement}\label{ch:threat}

This chapter defines the actors, adversaries, assumptions, and four security requirements used in
the design and evaluation. The model considers a potentially malicious directory operator and an
active network adversary, covering key substitution, warning censorship, split-view equivocation,
and the endpoint-compromise boundary.

% ============================================================================
\section{System Model and Actors}\label{sec:threat-system}

DUET models asynchronous communication between Alice and Bob through provider-operated messaging and
key-transparency services. Either client may be offline. The model has four actor roles: clients, the
messaging server, the directory server, and an independent auditor.

The \textbf{clients} hold private keys, publish public key material, and verify directory responses
locally. They are honest but may be intermittently connected. The \textbf{messaging server}
distributes X3DH pre-key bundles and relays ciphertext. The \textbf{directory server} stores the
verifiable directory, publishes a signed tree head each epoch, and answers lookup and monitoring
queries. A single malicious operator may control both servers, which form one trust domain in the
model. The \textbf{auditor} obtains signed heads and epoch disclosures, replays declared transitions
against committed roots, and compares views. It performs transition auditing and uses an independent
vantage for split-view (fork) detection.

\Cref{fig:threat-arch} shows three trust boundaries. Each client relies on the service operator for
availability but verifies every directory response. A Dolev--Yao network adversary can intercept, modify,
inject, replay, or drop traffic~\cite{dolevyao1983}. The auditor obtains its view separately from the
clients. A malicious operator may substitute keys or present different internally consistent
histories~\cites[Sections~1 and 3.3]{ietf-keytrans-architecture}
[Sections~4.2 and 5]{yadav2022fakekey}. DUET additionally considers censorship of warning writes.

DUET relies on the cryptographic assumptions in
\cref{sec:def-primitives,sec:def-vrf,def:x3dh}. The operator controls the directory's VRF secret key
and STH signing key. Given a fixed signed tree head, producing a valid inclusion proof for a value
absent from that directory state would require breaking the collision resistance of the hash
construction.

\phantomsection\label{sc:threat-a1}\paragraph{A1: Key Substitution.} A1 is the primary server-side substitution attack. A
compromised or coerced operator commits an attacker-controlled key under the victim's identity
and returns a valid inclusion proof for that malicious directory state. The proof establishes
that the key belongs to the signed state, not that it is the victim's authentic key. The
affected client detects the unexpected binding, and an established peer can learn of it through
the shared warning slot. The evaluation (\cref{ch:eval}) instantiates A1a at the global
identity slot and A1b at an immutable dual-index session slot.

\phantomsection\label{sc:threat-a2}\paragraph{A2: Warning Censorship.} A2 covers warning suppression
before and after commitment. Before commitment, a client that detects a key mismatch verifies the
warning slot. A proof-verified empty slot raises the compound A2 signal. After commitment, a returning
client's warning-slot check during windowed catch-up detects an in-window substitution only if the
warning remains present. If the directory operator removes the committed warning before that check,
the transition audit detects the invalid directory transition. Moreover, the separate persistence
component can retain deletion evidence (\cref{ssec:design-detection}).

\phantomsection\label{sc:threat-a3}\paragraph{A3: Network Man-in-the-Middle.} Without server
collusion, a Dolev--Yao adversary may replace Bob's identity key and signed pre-key with an
attacker-controlled pair whose signature verifies under the substituted identity. The attacker also
replaces or withholds the optional one-time pre-key, then establishes separate X3DH sessions with
Alice and Bob. As a result, Alice and Bob hold different conversation secrets and derive different
dual-index labels. The received identity key also differs from Bob's global VRF-bound identity
entry. When the directory is honest, comparing the received key with that entry detects the
substitution. A peer-slot absence can provide supporting evidence of the substitution but is not
sufficient on its own.

A post-compromise variant of the A3 network attack motivates the continuous mode defined in
\cref{ssec:design-modes}. An adversary that has compromised a session may inject a forged ratchet
key while the directory continues to operate correctly. Since the directory operations remain
internally valid, the transition audit cannot identify the forged key. Continuous mode authenticates
the public ratchet key at every epoch. A forged key either leads to a label the peer does not derive
or produces a fingerprint mismatch at the shared label. In either case, the update cannot be
accepted as consistent.

\phantomsection\label{sc:threat-a4}\paragraph{A4: Equivocation (Split-View).} A4 models the split-view
equivocation described in \cref{ssec:bg-ct2kt}. The directory server signs two different heads for
the same epoch and presents one to the victim client and the other to the auditor. Each head can be
valid in isolation, so only a cross-vantage comparison of the signed heads exposes the fork.

\phantomsection\label{sc:threat-a5}\paragraph{A5: Malicious Key Rotation.} A5 concerns an identity-key
change presented as a legitimate rotation. Since a legitimate rotation changes the identity key,
the changed binding alone cannot establish an attack. A malicious operator exploits this ambiguity
by substituting its own key during a claimed rotation. The peer re-fetches the global identity
entry. A valid cross-signature under the previously trusted identity key binds the new key to its
predecessor and authorises the rotation. Without a valid predecessor cross-signature, the new key
cannot be accepted as authentic.

\phantomsection\label{sc:threat-x1}\paragraph{X1: Endpoint Compromise (Boundary).} Once the adversary
controls the victim's private state, it can derive the same conversation secrets and labels and can
query the same directory entries. DUET can no longer distinguish the attacker from the victim. X1
therefore marks the endpoint-compromise boundary of DUET's key-transparency protection.
\Cref{fig:eval-attacktree} separates the key-substitution routes A1, A3, and A5 from the
concealment attempts A2 and A4 and from the endpoint-compromise boundary X1.

\section{Assumptions}\label{sec:threat-assumptions}

Under the attack scenarios defined above, the model excludes endpoint compromise (X1) by assuming
that honest clients retain control of their private state. The transition audit requires at least
one honest auditor. Split-view detection (A4) additionally requires a valid signed head obtained from
an independent vantage. However, the client-side checks for key substitution (A1), network
man-in-the-middle substitution (A3), and malicious key rotation (A5) do not require an auditor.
Warning censorship (A2) spans both cases. Its pre-commit check is client-side, while post-commit
removal is addressed through transition auditing or persistence evidence.

The initial binding also relies on a trust-on-first-use
assumption.\label{sec:threat-fair} DUET's monitoring guarantee begins only after a client pins a
binding obtained from an honest directory. If a malicious operator controls the initial value,
later monitoring detects changes but cannot establish whether the pinned value was authentic. A
network substitution during first contact (A3) remains detectable when the directory is honest
because the identity key in the substituted pre-key bundle differs from the peer's global
VRF-bound identity entry. \Cref{ch:discussion} discusses this limitation further.

\section{Security Requirements}\label{sec:threat-goals}

The adversary model and assumptions lead to four security requirements for DUET, denoted G1--G4.

\paragraph{G1: Key-Substitution Detection.} The affected client must detect server-side key
substitution (A1), network man-in-the-middle substitution with an honest directory (A3), and
malicious key rotation (A5). For an established conversation affected by A1 or A5, the peer must
receive an authenticated in-band warning. If the directory operator suppresses that warning,
verification must fail.

\paragraph{G2: Consistency Across Offline Windows.} A returning client that retains a trusted head
must verify that the current log extends that head without separately processing every missed epoch.

\paragraph{G3: Directory Privacy.} For an observer who has neither the VRF secret key nor the
corresponding VRF proof, a published VRF-derived global identity label must protect the associated user
identifier against ``offline dictionary attacks (also known as enumeration
attacks)''~\cite[Sections~1, 3.4, and 7.6]{rfc9381}.

\paragraph{G4: Fork Detection.} An honest auditor must detect split-view equivocation (A4) by
comparing the client-observed signed head with a different valid signed head for the same epoch
obtained from an independent vantage.
