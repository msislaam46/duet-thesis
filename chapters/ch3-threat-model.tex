\chapter{Threat Model and Problem Statement}\label{ch:threat}

This chapter defines the actors, adversaries, assumptions, and four security requirements that govern
the design and evaluation. The model combines a potentially malicious directory operator with an
active network adversary, then states the substitution, censorship, and equivocation scenarios
together with the endpoint-compromise boundary.

% ============================================================================
\section{System Model and Actors}\label{sec:threat-system}

DUET models asynchronous communication between Alice and Bob through provider-operated messaging and
key-transparency services. Either party may be offline. The four actors are the clients, the messaging
server, the directory server, and an independent auditor.

The \textbf{clients} hold their private keys, publish public key material, and verify directory
responses locally. They are honest but may be intermittently connected. The \textbf{messaging server}
distributes X3DH pre-key bundles and relays ciphertext. The \textbf{directory server} stores the
verifiable directory, publishes a signed tree head each epoch, and answers lookup and monitoring
queries. The two servers may be one malicious operator, so the model assumes no separation or
non-collusion between them. The \textbf{auditor} obtains signed heads and epoch disclosures
independently, compares views, and replays declared transitions against committed roots. This
independent vantage supports transition auditing and fork detection, and the client-side dual-index
warning does not require an auditor.

These actors define three trust boundaries, shown in \cref{fig:threat-arch}. The client depends on the directory server for availability but
verifies every response. The network is controlled by a Dolev--Yao adversary that can intercept,
modify, inject, replay, or drop traffic~\cite{dolevyao1983}. The auditor obtains its view separately
from the client. A malicious operator may substitute keys, censor warning writes, or present different
consistent histories~\cite{ietf-keytrans-architecture,yadav2022fakekey}.

DUET relies on the cryptographic assumptions stated in \cref{sec:def-primitives,sec:def-vrf,def:x3dh}. The operator holds its own VRF
and signing keys, but it cannot authenticate a value absent from a signed root without violating the
authenticated structure's collision-resistance assumption. Endpoint compromise defines the boundary
case \hyperref[sc:threat-x1]{X1}. The session and continuous authentication modes evaluated under this
model are defined in \cref{ssec:design-modes}.

\phantomsection\label{sc:threat-a1}\paragraph{A1: Key Substitution.} A1 is the primary server-side substitution attack. A
compromised or coerced operator commits an attacker-controlled key under the victim's identity
and returns a valid inclusion proof for that malicious directory state. The proof establishes
that the key belongs to the signed state, not that it is the victim's authentic key. The
affected client detects the unexpected binding, and an established peer can learn of it through
the shared warning slot. The evaluation (\cref{ch:eval}) instantiates A1a at the global
identity slot and A1b at an immutable dual-index session slot.

\phantomsection\label{sc:threat-a2}\paragraph{A2: Warning Censorship.} A2 covers two
warning-suppression routes. Before commitment, after detecting a key mismatch the client verifies the
warning slot, and a proof-verified empty slot raises the compound A2 signal. After commitment, removal
of a committed warning is an invalid directory transition detected by the transition audit, with the
separate persistence component able to retain deletion evidence. For a client using windowed catch-up, an in-window substitution is detected only
if the warning commits and remains present at the catch-up read (\cref{ssec:design-catchup}).

\phantomsection\label{sc:threat-a3}\paragraph{A3: Network Man-in-the-Middle.} With no server collusion, a Dolev--Yao adversary may
replace Bob's identity key and signed pre-key with an attacker-controlled pair whose signature
verifies under the substituted identity. The attacker also replaces or withholds the optional
one-time pre-key. The attacker can then derive the X3DH secret for the separate session established
with Alice. By establishing separate sessions with Alice and Bob, the attacker causes the
legitimate parties to hold different conversation secrets and so derive different dual-index
labels, which coincide only with negligible collision probability. The substituted bundle also differs from the identity entry stored under Bob's global
VRF-derived label. When the directory is honest, comparison with that global VRF-bound identity entry
detects A3. Labels derived from the two different conversation secrets provide supporting evidence,
though on their own they surface only as a peer-slot absence.

A post-compromise variant of A3 motivates continuous mode. An adversary that has already
compromised a session may inject a forged ratchet key while the directory itself continues to
operate correctly. The transition audit alone cannot identify the semantic mismatch because the
directory operations remain internally valid. Continuous mode instead authenticates the ratchet
key at each epoch. The forged key then produces either a label the other party does not derive
or a conflicting fingerprint at the expected label, causing the client to report a warning.

\phantomsection\label{sc:threat-a4}\paragraph{A4: Equivocation (Split-View).} A4 follows the split-view
threat studied in Certificate Transparency (\cref{ssec:bg-ct2kt}). The server signs two heads at one
epoch, one for the victim and one for the auditor, and no single client can distinguish the two
views. The cross-vantage comparison of the two heads exposes the fork.

\phantomsection\label{sc:threat-a5}\paragraph{A5: Malicious Key Rotation.} A legitimate rotation also changes the identity key, so a
changed key is not by itself malicious. A malicious server exploits this by substituting its own key
inside a rotation. The peer re-fetches the identity entry at the global VRF-derived label. If the identity key has changed, a valid cross-signature from the trusted predecessor binds the
new key to that predecessor and distinguishes an authorised rotation from an unauthorised
replacement. In the demonstrated A5 control, a missing
or invalid predecessor cross-signature causes rejection. The live client path currently relies on the
identity re-fetch and warning, while the cross-signature check is tested by the adversarial suite.

\phantomsection\label{sc:threat-x1}\paragraph{X1: Endpoint Compromise (Boundary).} Once the adversary controls the victim's
private state, it can derive the same conversation secrets and labels and can query the same
directory entries. The protocol can no longer distinguish the attacker from the victim. X1
therefore marks the endpoint boundary of key-transparency protection.
\Cref{fig:eval-attacktree} separates the key-substitution routes A1, A3, and A5 from the
concealment attempts A2 and A4 and from the endpoint-compromise boundary X1.

\section{Assumptions}\label{sec:threat-assumptions}

The model excludes \hyperref[sc:threat-x1]{X1} by assuming that honest clients retain control of their
private state. The transition audit and \hyperref[sc:threat-a4]{A4} fork detection require at least
one honest auditor with an independent view, whereas the client checks for
\hyperref[sc:threat-a1]{A1}, \hyperref[sc:threat-a3]{A3}, and \hyperref[sc:threat-a5]{A5} do not.

DUET's monitoring guarantee begins only after a client pins a directory binding while the directory
is honest.\label{sec:threat-fair} If a malicious operator controls the first value, later monitoring
detects changes but cannot establish its authenticity. With an honest directory, first-contact A3
remains detectable because the substituted pre-key bundle conflicts with the identity key under the
user's global VRF-derived label.
\Cref{ch:discussion} discusses the remaining trust-on-first-use limitation.

\section{Security Requirements}\label{sec:threat-goals}

The adversary model and assumptions give four security requirements, denoted G1--G4.

\paragraph{G1: Key-Substitution Detection.} Any public-key substitution by the server (A1, A5) or a
network adversary (A3) must be detected by the affected client. For an established A1 or A5
conversation, the peer must receive an in-band warning, or suppression must cause verification to fail.

\paragraph{G2: Consistency Across Offline Windows.} A returning client must verify that the current
log extends its last trusted state without processing every missed epoch.

\paragraph{G3: Directory Privacy.} It must be computationally infeasible for anyone other than the
directory operator to map a public directory label back to the corresponding user identifier.

\paragraph{G4: Fork Detection.} An honest auditor detects A4 by comparing the client-observed head
with a different valid head for the same epoch from an independent vantage. G4 alone depends on this
independent vantage.
