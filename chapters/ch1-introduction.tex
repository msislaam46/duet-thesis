\chapter{Introduction}\label{ch:intro}

Private messaging carries personal, professional, and civic communication. Signal~\cite{signal-home}
is an end-to-end encrypted messenger whose protocol has influenced other messaging
systems~\cite{signal-protocol-impact}. It uses server-hosted pre-key bundles for asynchronous
session establishment~\cite[Sections~3.1--3.3]{x3dh}. Encryption protects a conversation only when the sender uses the
intended recipient's authentic key, so a substituted binding can establish an encrypted channel with
an attacker while the conversation still appears secure.

Signal's traditional defence is a manual Safety Number comparison~\cite{safetynumbers} over an independent channel. The
comparison is sound when completed, but one study found that only about 14\% of unguided
pair--application trials succeeded and that just two of twelve pairs completed the ceremony in any
tested application~\cite{vaziripour2017}. A one-off comparison also does not monitor later key
changes, so the ceremony must be repeated after every new identity binding.

Key transparency commits public-key directory states to a verifiable, append-only history, and Signal
deploys this approach through optional Automatic Key Verification~\cite{signal-akv}. The systems
surveyed in \cref{ch:background} expose changes through self-monitoring, auditing, witnesses, or
whole-directory verification, but none gives one party an automatic, conversation-specific channel for
warning the other. Moreover, per-epoch monitoring makes a returning client's work grow with the number of
missed epochs.

A suitable design must therefore verify keys automatically, report substitution to both parties in
band, reject missing or invalid proofs, and let an offline client verify missed history without
retrieving one proof per epoch.

\section{Aim and Approach}\label{sec:intro-aims}

We propose DUET (\emph{DU}al-index, \emph{E}poch-windowed \emph{T}ransparency), which performs
key-substitution checks automatically and reports warnings in band. These checks require no separate
manual comparison. However, detection requires additional label-bound lookups and writes, which do
not change the asymptotic complexity of an individual lookup proof. DUET combines the dual-index
warning scheme with windowed consistency verification and is integrated into a Signal Desktop
prototype (\cref{ch:impl}). The windowed consistency mechanism replaces one proof per missed epoch
with a single proof whose size grows logarithmically in the endpoint log sizes.

DUET does not prevent a malicious directory operator from denying service. Its narrower goal is to
ensure that a substituted key, an invalid or missing proof, or an inconsistent directory history
causes verification to fail, preventing the client from silently accepting an attacker's key.
\Cref{ch:threat} formalizes this distinction between detectable interference and availability.

\section{Contributions}\label{sec:intro-contributions}

This thesis makes four contributions.

\paragraph{Conceptual.} The \emph{dual-index warning scheme} derives a separate lookup label for each
party and a shared warning label from the conversation's shared secret. The warning label identifies
a shared slot to which either party can write an authenticated warning payload. For an honestly
established and monitored conversation, a malicious server cannot predict and pre-position that
slot before the label is first used. Before a warning is committed, a key mismatch along with
proof-verified absence at the shared warning slot raises the warning-censorship alarm. If the
committed warning is later removed, the transition audit rejects the invalid directory transition.
The committed warning allows both parties to detect the substitution automatically and in band
(\cref{sec:design-dual}).

\paragraph{Cryptographic.} The cryptographic contribution applies an RFC~9162~\cite{rfc9162}
distant-head consistency proof to offline monitoring. With a retained signed-head checkpoint, a client
re-verifies missed history using one proof for the complete window. Its size is logarithmic in the
endpoint log sizes, while the repeated-proof baseline grows with the number of missed epochs
(\cref{sec:design-windowed}, \cref{lem:windowed-size}). A same-head consistency lemma (\cref{lem:dualindex-consistency}) establishes
that Alice's peer lookup and Bob's self-check cannot authenticate different values under one signed
head. \Cref{ch:design} establishes these properties, and \cref{ch:eval} evaluates their costs.

\paragraph{Systems.} The systems contribution instantiates ACKA's abstract log
component~\cite{dowling2023acka} as the DUET directory through the \texttt{duet} Rust crate,
which provides the HTTP directory server and auditor process. A
client verifier is integrated into a modified build of Signal Desktop~(\cref{ch:impl}). Shared protocol
operations are checked for byte-for-byte agreement using cross-language test vectors.

\paragraph{Empirical.} The benchmark evaluation yields four main findings. At a matched directory size, the implemented
VRF-indexed lookup proof is comparable in size to the corresponding CONIKS
proof~\cite{melara2015coniks}. Detection adds label-bound lookups that reuse the same proof format,
leaving individual proof size unchanged. Median full client verification remains below
\SI{150}{\micro\second} through $10^7$ labels. A 30-day offline window with hourly epochs requires
one proof containing \num{320} raw
consistency-path hash bytes, compared with \num{222528} bytes for the synthetic repeated-proof
baseline. Separately, the STRIDE and MITRE ATT\&CK evaluation distinguishes the attacks detected by
the implemented controls from the residual risks that remain (\cref{ch:eval}).
