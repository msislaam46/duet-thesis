\begin{abstract}
The security of end-to-end encrypted messaging rests on an assumption that its cryptography does
not itself establish. The public keys handed out by the server must be authentic. Signal's
original built-in defence, the Safety Number, covers only the long-term identity keys and requires a
manual out-of-band comparison that a usability study found few pairs complete without guidance.
Key transparency makes unauthorized key changes detectable by committing public-key directory states
to a verifiable, append-only log, and is now deployed in production systems. Existing
approaches expose changes through self-monitoring, external auditing, witness validation, or
whole-directory verification. None of these provides an automatic, conversation-specific channel
through which a party that detects a substitution can warn its peer. Returning clients that monitor
every epoch also incur a cost that grows with the number of missed epochs and therefore with the
time spent offline.

To close both gaps, this thesis proposes DUET (DUal-index, Epoch-windowed Transparency), a key
transparency scheme for secure messaging that remains aligned with the emerging IETF Key
Transparency protocol and is demonstrated through an implementation in Signal Desktop. DUET
rests on two underlying mechanisms. First, the
\emph{dual-index warning scheme} derives two party-specific lookup labels and a shared warning
label from each conversation's shared secret. In an honestly established
and subsequently monitored conversation, these enable automatic, in-band detection of key
substitution by both parties without additional user interaction.
Second, \emph{windowed consistency proofs} replace per-epoch catch-up with a single consistency
proof between the last trusted and current tree heads, so a client requests and verifies one proof
rather than one for each of the $W$ missed epochs, with size logarithmic in the endpoint log sizes
rather than linear in the epochs it missed.

Benchmark results show that, at a matched directory size, DUET's lookup proof is comparable in size
to the corresponding proof in CONIKS. Median full client verification remains below
\SI{150}{\micro\second} through ten million labels, and a month of missed epochs is covered by one
short proof rather than one per epoch. A two-client Signal
Desktop prototype runs verification automatically in the background and raises key-substitution
warnings in band. An independent auditor checks the public-key directory for invalid changes and
conflicting signed views.
\end{abstract}
