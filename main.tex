\begin{abstract}
The security of end-to-end encrypted messaging rests on an assumption its cryptography does
not itself establish: that the public keys the server hands out are authentic. Signal's
original built-in defence, the Safety Number, covers only the long-term identity keys and requires a
manual out-of-band comparison that few users ever complete, leaving a malicious or compromised
directory free to substitute a key undetected. Key transparency makes the directory auditable
and supports detection of unauthorized key changes by publishing it as a verifiable, append-only log;
it now ships in production (most recently as Signal's optional Automatic Key Verification). But deployed
designs still leave two gaps: a key substituted in the log itself is noticed only by its owner,
with no in-band channel to warn the peer, and a client returning after an offline period must
pay a monitoring cost that grows with the number of missed epochs, and so with the time spent
offline.

To close both gaps, we propose DUET (DUal-index, Epoch-windowed Transparency), a key
transparency scheme for secure messaging that remains aligned with the emerging IETF Key
Transparency protocol and is demonstrated through an implementation in Signal Desktop. DUET
rests on two underlying mechanisms. First, the
\emph{dual-index warning scheme} derives, from each conversation's shared secret, a pair of
participant-specific lookup labels together with a shared warning label, enabling automatic,
in-band detection of key substitution, in an honestly established and subsequently monitored
conversation, by both participants without additional user interaction.
Second, \emph{windowed consistency proofs} replace per-epoch catch-up with a single consistency
proof between the last trusted and current tree heads, so a client requests and verifies one proof
rather than one for each of the $W$ missed epochs, with size logarithmic in the endpoint log sizes
rather than linear in the epochs it missed.

In component measurements of the verification chain, the VRF-indexed lookup proof has a median
size of \SI{817}{B} on a directory of $10^6$ labels, comparable to a dense Merkle-log inclusion
proof at the same directory scale, and median full client verification stays below
\SI{150}{\micro\second} through $10^7$ labels, growing far more slowly than $N$. At a one-month
window, the single windowed proof reduces raw consistency-path hash bytes by a factor of
\num{695} against the evaluation's synthetic per-epoch baseline, which re-fetches one proof for
each missed epoch.

Together, these results show that an in-band peer-warning channel and a single distant-head
consistency proof can be added to a CONIKS-style messaging directory without changing its proof
asymptotics. The implementation exercises the design in a two-client Signal Desktop prototype:
the advisory client path derives conversation labels from a deterministic session-secret
stand-in, verifies fetched keys in the background, and raises substitution warnings in band,
while a separate auditor process verifies directory transitions and detects signed equivocation
between the demonstration's two server views. The integration and the measurements together
provide a concrete basis for binding DUET to live Signal session state.
\end{abstract}
